# 首次试用的两份 brief

本目录全部为自制合成案例，无真实用户稿件内容。它们帮助理解填写方式；实际写入仍需用户提供目标并授权范围。

先运行 `figma-local guide refine` 或 `figma-local guide design`。参考对应 JSON，将适合自己任务的字段填入生成的 `.figma-agent/brief-<模式>.json`。保留已有 brief，避免整文件覆盖丢失你的内容。

- `refine.json`：现有资料卡的正文遮挡问题，强调保留内容和既有样式。
- `design.json`：从空白 Frame 设计资料收藏首页，采用文字视觉方向，无需先找图即可进入结构讨论。

两份示例的 `acceptedDirection` 均为 null。从零设计案例的 `designFoundations` 留空。执行 guide-check 会显示可规划、待确认；选择方向并形成设计基础之后，再填写这些字段。

`designSystem` 与 `protectedRegions` 使用非空字符串数组，每项说明位置、用途和约束；暂无内容用 `[]`。`references` 使用对象数组，格式见 [工作流](../../docs/workflows.md)。

## 给 Agent 的首次任务

精修：

> 读取我的 brief-refine.json。先 inspect、design-system、preview，并读取每个任务的结果。解释遮挡的原因，列出将修改和保留的节点，给我一个局部方案。确认后先修改一张卡片。保留完整正文与旧版，逐项核对 before/after 和截图，最后实际点击标签。遇到未知状态先读回，保留证据。

从零设计：

> 读取我的 brief-design.json。先提出搜索优先和列表优先两种结构草图，说明各自如何服务主要任务。我选择后，再确定字体、颜色、间距与组件规则。先完成搜索区和一张资料卡，通过截图评审后再扩展页面。分别验证长内容、空态、错误态和来源返回。每批原生图层返回节点 ID，全部采用当前 CLI 的运行和结果读取流程。

## 是否需要上传参考图

有明确喜欢的视觉方向时，准备 2–3 张获准使用的参考，说明每张借鉴什么。把图保存在本地，在 references 中填入路径，再交给你使用的 Agent 查看。桥接无需上传图片到独立云服务；Agent 使用外部模型时仍遵循该模型的数据处理方式。

没有参考图时，先填写形容视觉风格和信息密度的文字。Agent 应给出可比较的结构与局部视觉样稿，再由你选择。CLI 检查素材和 brief 的完整性，视觉质量需要查看成稿后评审。
