# 首版范围与实施顺序

## 产品目标

用户安装并连接一次，通过现有 Agent 用自然语言提出需求，在 Figma 中快速看到结果并持续迭代。用户只接触「已连接」「执行中」「正在重连」「需要你处理」四种运行状态。

首版限定 macOS、Figma Design、一个打开的文件、一个写入 Agent。默认修改当前选中的 Frame；选择不明确时用中文询问。自动上下文读取同文件内的相关参考区域，跨区域写入需要确认。

## 实施顺序

1. 连接：固定插件、一次配对、本地长驻 Session Manager；验证隐藏面板、页面切换、原型预览、后台及睡眠后的恢复。
2. 上下文：先取得当前选择及目标截图，后台补充相关的 2–3 个参考页、已用组件、变量、字体、样式；缓存并增量更新。文档摘要为可选输入。
3. 操作：文字、间距、尺寸、颜色、字体、变量绑定、实例创建、实例属性、Auto Layout、对齐、分布、简单原型连接。原始 JavaScript 进入开发者模式。
4. 检查：自动读回修改结果、必要时截图对照。成功只留有限最近记录，错误再收集诊断。
5. 交付：五场景真实案例达标后整理 README、真实徽章、许可证和公开素材，提交 GitHub。

## 五场景的首版边界

| 场景 | 首版交付边界 |
| --- | --- |
| 从零设计 | 根据明确需求及参考，在既有设计语言中新增一个页面，原生可编辑 |
| 已有稿精修 | 当前 Frame 的文字、样式、间距与布局迭代，保留原组件关系 |
| Design to Code | 一个授权页面的高保真 HTML、对应素材及关键交互，不建设通用转换器 |
| Code to Design | 一个运行网页的原生组件与画板重建，不建设双向同步 |
| 交互原型 | 主要路径的跳转、返回、弹层、状态及滚动，业务服务用明确模拟状态 |

每场景仍需独立测试用例、视觉检查、适用的真实点击与至少 8/10 的评分依据。前两项优先验证日常路径；其余复用同一运行时，不增加三套产品入口。

## 保留的隐形边界

- 默认只修改用户选中范围，跨区域先确认。
- 连接和执行状态不明时禁止重放，保留尚未确认操作的必要信息。
- 删除页面、大范围删除、修改共享组件或全局变量时简明确认。

## 暂缓范围

完整文档回滚、复杂事务体系、证据导出标准、额外 JSON Schema、设计合同、多 Agent 写入、多文件同步、团队审计、共享组件自动发布、空白文件一句话生成完整产品、Motion 功能对齐。既有实现与测试先保留，替代路径验证后再清理。

## 必须实测的门槛

- 一次安装和一次连接；普通用户无需终端、节点 ID、任务 ID、JSON 或脚本。
- 温启动恢复目标小于 3 秒；常见修改 10 秒内可见。
- 连续 8 小时、100 个任务；无丢失写入、无重复写入。
- 页面与预览切换、后台和睡眠唤醒后自动恢复。
- 10 个常见任务至少 8 个自动找到正确组件、变量和参考。

## 持久会话开发入口

高层改色开发命令为 `figma-local fill '#3366FF'`，由Agent调用，使用当前单一选区。仅接受六位颜色及一个可见纯色填充，保留透明度与混合模式；锁定、主组件、样式/变量绑定、多层、渐变、图片和混合填充均拒绝直接覆盖。CLI/HTTP/执行器集成中的文档API为模拟；真实画布已验证独立Rectangle改色、50%透明度保持、独立读回与恢复，不能扩展为全部图层类型已验收。

由 Agent 调用：

```sh
node bin/figma-local.mjs setup <已确认的目标链接>
node bin/figma-local.mjs serve
```

固定状态位置为macOS用户目录的 `Library/Application Support/local-figma`。同一目标重复准备保留绑定与配对；已有本地绑定优先，其他目录才使用固定会话，避免静默切换目标。

固定插件模式的同端口重启、未确认任务不重投、原插件结果接续、旧CLI凭证失效与0600配对权限均有自动测试。当前仍使用前台进程；开发入口尚不等同于普通用户的一次安装体验。
