# 首版审查入口

## 这版能帮用户做什么

连接有编辑权限的 Figma 文件后，用自然语言让本地 Agent 精修现有稿，或按内容、参考和方向选择逐步制作新 UI。结果是原生可编辑图层。

用户准备 Figma 链接和需求，首次导入开发插件；使用期间保持桥接终端及插件开启。Agent 承担脚本、brief 和命令操作，用户确认方案并查看成果。当前通过验收的环境是 macOS + Figma Desktop + Node.js 22 及以上。

1. [README](../README.md)：安装、连接和项目定位。

## 两种典型任务

以下两项为日常入口；完整首版还包含 Design to Code、Code to Design 与交互原型，逐项状态见[五场景验收](scenario-acceptance.md)。

**已有稿精修**：例如“这张卡片正文遮挡标签，只调整正文区域，保留完整内容和现有样式”。Agent 读取目标、复用资源，提出局部方案，修改后展示截图与差异。真实桌面已验证局部文字修改、Auto Layout、截断、滚动和回顶点击。

**从零设计**：提供页面目的、真实内容、尺寸与视觉方向；有参考图时建议提供 2–3 张并标注借鉴点。Agent 先给结构方向，选定后制作一个关键区域，看过截图再扩展。没有参考图时可从文字方向开始。当前已有参考驱动的公开任务概览案例、创建脚本与结构检查，限定主路径通过真实点击；高质量成稿仍需针对具体需求进行设计判断与视觉评审。

## 差异化看什么

关注一次修改能否说清“改哪里、改了什么、结果如何”：显式目标绑定、写入前保存结构、脚本留存、离线结果与差异、失败后避免重复执行，加上上述两条使用流程。CLI/JSON 接口可由不同本地 Agent 使用。当前不宣称同类工具没有这些能力，也不宣称速度或设计质量领先。

## 安装本地审查包

在空项目目录中安装收到的 tgz，再按 README 连接自己的目标：

```sh
npm install -g /absolute/path/to/figma-local-runtime-0.1.0-alpha.1.tgz
figma-local help
```

路径换成审查包实际位置。包尚未上传 npm；本地包和源码均可供审查。无需 Figma REST API key，也无需配置独立云端桥接服务。

## 当前明确限制

- 插件和终端需保持打开；原型预览后应返回编辑页再继续任务。
- 只运行可信脚本；范围核对不构成脚本沙箱。
- 完整自动回滚尚未提供，失败后先读回核验。
- 已验证单个授权文件与 macOS 环境，其他环境尚未作兼容承诺。

自动测试、真实桌面记录和 tarball 隔离安装分别证明对应范围，不替代成稿评审。最新回归数量与未完成门槛统一见[发布审查](release-readiness.md)。
