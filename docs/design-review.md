# 设计质量评审

适用于现有稿精修和从零设计。结构校验、截图检查与真实交互分别记录，任何一步未执行均保留待检查状态。CLI 不自动判断审美质量。

## 每次小批修改

1. 保存修改前 preview 的任务 ID；查看截图，明确一个待解决问题。
2. inspect 和 design-system 后列出受影响节点与保护范围；检查内容真源、摘要与派生区域关系。
3. 执行小批脚本，读取 result、diff、validate；执行失败先核对实际文档。
4. 再 preview，使用相同目标和导出尺度并排检查前后变化。局部截图之外，再检查包含相邻区域的授权画板，防止漏掉外部遮挡。
5. 有原型时进入预览真实操作，检查进入、返回、滚动和操作区域。完成后再扩大修改范围。

## 共用检查标准

| 维度 | 检查方法 | 需要修正的迹象 |
| --- | --- | --- |
| 内容正确 | 对照真源逐段核查；完整视图与摘要分别检查 | 文案遗漏、派生区混入正文、长图用了精简内容 |
| 信息层级 | 查看整页，再看关键区域；解释用户第一步和第二步动作 | 多个主按钮竞争、标题正文难区分、说明卡片抢占主任务 |
| 排版一致 | 读回字体、字号、行高并检查截图；富文本按范围检查 | 无意 Mixed、长行阅读困难、编号换行、基线跳动 |
| 布局边界 | 检查长内容及滚动首中尾；同时看相邻区域 | 遮挡、越界、错误截断、按钮或标签意外收缩 |
| 组件复用 | 对照已用组件、样式与变量；记录有意偏离的原因 | 局部调整破坏系统一致性、无意解除实例或变量绑定 |
| 原生可编辑 | 抽查 Text、Frame、Instance 与层级 | 整页被压成位图、标题正文失去编辑能力 |
| 交互连贯 | 实点主要路径，从不同来源进入并返回 | 错误目的地、返回丢失来源、固定区随滚动移动 |

现有稿精修额外检查：原问题是否解决、保护内容是否保持、是否引入无关视觉变化。

从零设计额外检查：整体方向是否获得选择、关键区域是否先通过评审、各区域是否遵循同一排版和组件规则、长内容/空态/错误态是否覆盖。

## 可复制的评审记录

在本地项目保留下列信息，公开分享前脱敏：

```text
场景：refine / design
目标与允许范围：
内容和设计依据：
选定方向及选择人：
修改前 preview 任务 ID：
run 任务 ID：
修改后 preview 任务 ID：
结构检查：通过 / 有问题 / 未执行（证据与问题）
视觉检查：通过 / 有问题 / 未执行（证据与问题）
真实点击：通过 / 有问题 / 未执行（已测路径）
保护内容核对：通过 / 有问题 / 未执行
剩余问题和下一批范围：
用户评审：待评审 / 接受 / 需要修改
```

允许记录局部通过，同时保留整页未验证项。把这份记录当作可核查的交接材料，避免用一个总分掩盖内容、视觉或交互上的具体缺口。
