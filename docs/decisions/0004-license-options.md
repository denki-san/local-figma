# ADR 0004：采用 Apache-2.0

状态：Decided / Accepted，标准正文已落盘，项目版权署名待确认

## 目标

项目以公益、生态扩散和社区共建为目的，需要一个宽松、包含明确专利授权、适合基础设施生态集成的许可证。

## Decision

- 决定采用 Apache-2.0。
- 已加入仓库根目录 `LICENSE` 标准文本，来源为 Apache 官方许可正文；附录的方括号内容保留为官方使用示例，不表示本项目版权主体。
- 正式发布前补齐明确的项目版权署名。
- 贡献指南、包元数据和发布产物届时统一声明 Apache-2.0。

## Considered alternatives

### Apache-2.0

- 宽松，包含明确专利授权。
- 适合希望广泛集成和企业采用的基础设施项目。
- 无法阻止第三方托管或商业封装。

### MIT

- 简单、熟悉、采用门槛低。
- 专利条款不如 Apache-2.0 明确。
- 同样无法限制第三方托管。

### MPL-2.0

- 文件级 copyleft，允许与闭源系统组合。
- 修改核心文件需要公开，治理边界更复杂。
- 部分企业法务评估成本高于宽松许可证。

### AGPL-3.0

- 对网络服务修改版提供更强公开要求。
- 可能保护 Hosted 竞争边界。
- 会明显降低部分企业采用和生态嵌入意愿。

## Consequences

- 便于个人用户、Agent 生态和企业项目采用、修改与集成。
- 明确的专利授权适合运行时与协议类项目。
- 无法禁止第三方托管或商业封装；这与当前公益和生态扩散目标一致。
- 正式发布前仍需确定版权主体，并检查所有第三方依赖许可证兼容性。
