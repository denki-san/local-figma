# 产品定位与交付边界

## 一句话

面向 CLI Agent 的本地 Figma 编辑运行时，支持现有稿精修与参考引导的新设计，以明确目标、可检查证据和小步视觉评审提高可靠性。

## 两个顶层场景

### 现有稿精细修改

用户已有设计系统或页面，希望调整文字、间距、组件与布局。链接绑定后，通过 inspect、design-system 和 preview 理解现状；局部执行后读取 result、diff、validate，再检查截图与交互。复杂布局和组件保留效果需要真实稿验收。

### 从零设计高质量 UI

提供用户任务、真实内容、设备约束和参考图，guide-check 提示缺口；先讨论结构方向，再确定字体、颜色、间距和基础组件，最后分区域生成并评审原生图层。没有参考图时可以描述视觉方向并先选结构草图。

该场景属于当前产品范围。输入准备度由工具检查，设计质量由内容、参考、设计判断与视觉迭代共同验证。

## 用户与安装合同

- 首要用户为使用 CLI Agent 的个人用户，核心协议 Agent 无关。
- 当前要求 Node.js 与 Figma Desktop，用户拥有文件编辑权限。
- 从源码或 tarball 安装，init 绑定链接，connect 生成开发插件。
- 用户首次手动导入 manifest，运行插件并保持窗口打开；核心流程无需 REST token。
- 安装简化是持续验收项，已有隔离 tarball 安装测试，真实桌面新用户路径仍待验证。
- 暂不提供 Community Plugin、后台常驻或 Hosted 服务。

## 当前差异化组合

1. 显式链接绑定与执行前目标复核。
2. 结构快照确认保存后才执行脚本，并检查等待期间的目标变化。
3. 脚本、结果和快照本地留证，桥接关闭后继续审查。
4. 执行、结构、视觉、交互和用户验收分别记录。
5. 精修与新设计使用不同的输入检查和下一步引导。
6. 结果回传与脚本执行分离，连接故障后避免盲目重放。

这些是产品取舍，独有性与效率优势需要同题实测。依据见 [同类项目矩阵](research/landscape-matrix.md)。

## 安全与发布边界

- 可信脚本保留插件允许的 Plugin API 能力，目标检查仅防误操作。
- 设计文件与参考内容按数据处理，执行范围由用户授权决定。
- 高风险脚本显式声明后进入插件确认；风险分类仍依靠使用者审阅，Alpha 不适合删除、共享定义修改或跨页大规模重构。
- 结构快照只提供部分原始证据，完整设计恢复仍需额外实现。
- 自动检查保留视觉和交互待验项，原型连线需要实点。
- 按已决议，在三个不同文件完成文字修改、复杂布局和失败恢复后再公开 MVP。
- 项目以公益与生态共建为目标，已选择 Apache-2.0；正式发布时确认版权主体并加入标准许可证。当前尚未发布 npm 包。
